# 01. RRSI 논문 분석

> 대상 논문: *RRSI: Regularized Recursive Self-Improvement of Agent Harnesses* (arXiv [2609.24972](https://arxiv.org/abs/2609.24972) v2, 2026-09-25, Google Cloud AI Research 외). 참조 구현: `github.com/google-research/rrsi` (Apache-2.0, commit `be50316`).
> 이 문서는 논문의 번역이 아니다. 문제·방법·수식·결과를 우리 말로 요약하고, XGEN 에 주는 시사점을 덧붙인 분석 노트다. 원문 표현을 그대로 옮긴 곳은 따옴표와 출처 절로 표시했다. 수식과 식 번호는 다른 문서와 코드가 교차 참조하므로 논문 표기 그대로 둔다. 논문-코드 차이는 [02](02-rrsi-reference-code.md), 기호표·정의역·검산 벡터는 [05](05-formula-reference.md) 에 있다.

## 0. 한 줄 요약

하네스가 바뀔 수 있는 범위 Ω(H)는 제한하지 않는다. 대신 진화가 **어떤 궤적으로** 움직이는지를 정규화한다. 제안 단계에서는 한 번에 묶는 편집 수를 줄여 가고, 지난 편집의 성패를 근거로 쓰며, 정체되면 안 건드린 구성요소로 시선을 돌린다. 선택 단계에서는 평가 전에 누설을 거르고, 잡음으로 설명되는 이득은 받지 않으며, 비용 증가는 이득으로만 정당화하고, 기여가 끊긴 구성요소는 제거 대상으로 돌린다.

## 1. 문제 정의

### 1.1 에이전트 = 정책 + 하네스

- 에이전트는 `A = (π, H)` 다. π 는 가중치를 고정한 backbone LLM, H 는 그 밖의 모든 것(프롬프트, 제어 흐름, 도구와 그 설명, 메모리·스킬 파일, 컨텍스트 관리)이다.
- 태스크 x 에서 궤적 `τ ∼ A(·|x)` 가 나오고 검증기가 `r(x, τ) ∈ [0,1]` 을 준다(코딩은 unit test, 업무형 workspace 는 LLM judge 의 criteria 판정).

### 1.2 목적함수 (Eq.1)

```
S(H; D) = E_{x∼D} E_{τ∼A(·|x)} [ r(x, τ) ]
C(H; D) = E_{x∼D} E_{τ∼A(·|x)} [ c(τ) ]          c(τ) = 궤적이 소비한 policy token 수
```

성능 S 와 비용 C 의 짝이다. 비용 단위는 달러가 아니라 **정책 토큰**이다.

### 1.3 하네스 진화 루프 (Eq.2, Eq.3)

```
𝓗_t = {H_t^(1), …, H_t^(m_t)} ∼ P0(· | H_t, 𝓕_t),     H_{t+1} = argmax_{H' ∈ 𝓗_t ∪ {H_t}} Ŝ(H'; D_evolve)      (2)

Ŝ(H) = 1/(k|D_evolve|) Σ_{x∈D_evolve} Σ_{j=1..k} r(x, τ_x^(j)),
Ĉ(H) = 1/(k|D_evolve|) Σ_{x∈D_evolve} Σ_{j=1..k} c(τ_x^(j))                                                        (3)
```

- 매 라운드 incumbent H_t 를 evolve 집합에서 돌려 피드백 𝓕_t 를 만들고, 제약 없는 제안 과정 P0 가 후보를 낸 뒤, 같은 집합에서 점수가 가장 높은 것을 다음 incumbent 로 삼는 것이 기존 방식이다. Ŝ·Ĉ 는 태스크당 k 회 시행의 표본 평균이다.
- 논문의 핵심 진단: 같은 D_evolve 를 라운드마다 다시 쓰므로 측정이 **적응적**이 된다. 라운드 t 의 후보는 앞 라운드의 같은 태스크 결과에 맞춰 만들어진다. 표현력이 큰 탐색 공간에서 이런 재사용은 과적합을 구조적으로 부른다.

### 1.4 과적합을 만드는 세 행동

| 행동 | 내용 | RRSI 의 대응 장치 |
|---|---|---|
| 벤치마크 맞춤 | 태스크명·정답·특정 값을 하네스에 새김 | 평가 전 누설 심사, 헌법의 금지 규칙 |
| 잡음 추종 | 평가 잡음으로 우연히 높게 나온 후보를 승격 | 잡음 바닥(Eq.5), 대역 안 규칙(Eq.17), k 시행 |
| 복잡도 누적 | 메커니즘 개선 없이 evolve 점수만 올리는 덧붙임 | L0 편집 예산(Eq.4/9), 비용 규칙(Eq.7), 가지치기(Eq.14) |

세 행동 모두 evolve 점수와 이전(transfer) 성능 사이의 간극을 넓힌다.

### 1.5 일반화의 정의

진화한 하네스가 태스크 설명·도구 인터페이스·검증기가 **모두 다른** 미관측 벤치마크에서도 좋아지는 것. 실험은 evolve / ID held-out / OOD 로 분리한다.

## 2. 방법 개관

### 2.1 정규화 관점 (Sec 3.1, Figure 2)

- Ω(H) 는 일부러 열어 둔다. 프롬프트, 제어 흐름, 설정, 컨텍스트 관리, 도구, 스킬, 메모리, 서브에이전트를 모두 고치거나 추가·삭제할 수 있다.
- 정규화는 두 곳에 건다. **제안 쪽**은 한 라운드의 적응 용량을 얼마나, 어디에 쓸지 제한하고, **선택 쪽**은 어떤 개선이 영구 상태가 될 자격이 있는지 제한한다.
- 고전 정규화와의 대응은 비유일 뿐 수학적 동치가 아니라고 논문은 거듭 밝힌다. 편집 예산 ↔ L0(독립 편집 수 상한), 구조 가지치기 ↔ Lasso/L1(비생산 구성요소 통째 제거), 복잡도 인지 수락 ↔ Ridge/L2(전체 자원 발자국의 성장 억제).

Figure 2 는 일곱 장치로 정리된다. 제안 쪽: A 담금질 업데이트 희소성, B 증거 기반 신용 할당, C 구조적 탐색. 선택 쪽: D 누설 심사, E 잡음 보정 바닥, F 복잡도 인지 수락, G 구조 가지치기.

> **그림-본문 불일치(우리 확인)**: Figure 2 는 F 에 "L1-style", G 에 "L0-style" 표식을 붙였지만 본문 Sec 3.3 과 Appendix C 는 F = Ridge/L2, G = Lasso/L1, 편집 예산 = L0 로 정의한다. 참조 구현 `rrsi/config.py` 는 β 규칙을 "L1 cost rule" 이라 부른다. 우리는 **본문 정의를 정본**으로 쓴다. 수식은 어느 쪽이든 같다.

### 2.2 전이 규칙

```
Proposal :  H' ∼ P_reg(· | H_t, feedback)
Selection:  H_{t+1} = best admissible H'  or  H_t
```

논문 그림의 요약 문장(인용, Figure 2): "Set H_{t+1} to the best admissible candidate if it improves robustly; otherwise keep H_t."

## 3. 제안 분포의 정규화 (Sec 3.2)

### 3.1 담금질 업데이트 희소성 (Eq.4)

한 후보에 묶이는 독립 편집 수를 라운드 t(전체 T)마다 상한한다.

```
b_t = ⌈ b_min + (b_max − b_min) · ½ (1 + cos(π t / T)) ⌉                                      (4)
```

- 초반에는 여러 편집을 묶어 새 메커니즘을 찾게 하고, 후반에는 한두 개로 좁혀 효과를 특정 편집에 귀속할 수 있게 한다. 편집을 이진 지시자로 보면 예산은 그 cardinality 상한, 즉 업데이트에 대한 L0 제약이다.
- 바깥 괄호는 **천장 함수**다(본문 p.5 와 Algorithm 1 line 2 를 원본으로 대조).
- **구현 함정(우리 분석)**: t = 0..T−1 만 돌면 천장 때문에 b_t 가 b_min 에 닿지 않는다(T=20, b_min=1, b_max=4 이면 t=19 에서 b=2). b_t = b_min 은 t = T 에서만 성립한다. Table 5 가 b_min 을 "마지막 라운드 예산"이라 부르는 것과 어긋나지만 참조 코드도 같은 값을 낸다. 표는 05 문서.

### 3.2 증거 기반 신용 할당

같은 evolve 집합을 다시 재는 일은 매번 적응적 관찰이 하나 더 쌓이는 것이므로, 이미 반증된 가설을 다시 시험하면 증거 없이 용량만 쓴다(논문은 Dwork et al., 2015 를 근거로 든다). 그래서 평가한 후보마다 **구성요소, 가설, 소스 diff, 점수 변화, 비용 변화, 수락 여부**를 남기고 proposer 가 이후 라운드에서 이 이력을 읽는다. 거부된 메커니즘은 부정 증거로, 채택된 메커니즘은 신용으로 남는다. Eq.4 로 후반 후보가 작아질수록 귀속이 쉬워져 두 장치가 서로를 돕는다.

### 3.3 구조적 탐색

이력을 보면 proposer 가 한 종류의 편집(예: 프롬프트만)에 갇혔는지 드러난다. 직전 w 라운드의 진척이 잡음 대역 δ 안이면 **정체**로 판정하고, 아직 측정된 적 없는 구성요소에 제안 슬롯 일부를 예약한다. 엔트로피 정규화와 비슷한 역할이지만 하네스가 가질 수 있는 메커니즘 자체는 바꾸지 않는다.

## 4. 후보 선택의 정규화 (Sec 3.3)

후보는 여러 기준을 **모두** 만족해야 한다(비보상적, non-compensatory). 한 기준의 우위로 다른 기준의 실패를 메울 수 없다.

### 4.1 누설 심사

평가 **전에** critic 이 diff 를 읽고 태스크명·엔티티명·정답·특정 값 등 evolve 벤치마크 고유 내용을 넣은 편집과, 실제로는 작동하지 않는 **비활성 기계장치**를 넣은 편집을 거부한다. 대상은 구성요소 종류가 아니라 내용이다. 평가 전에 거르므로 누설 후보는 부풀려진 점수를 받을 기회 자체가 없다.

### 4.2 잡음 보정 바닥 (Eq.5)

진화 전에 base 하네스를 반복 평가해 잡음 대역 δ 를 잰다. S★ 는 지금까지의 최고 evolve 점수다.

```
Ŝ(H') ≥ S★ − δ                                                                                 (5)
```

잡음으로 보일 만큼 작은 퇴행이 쌓여 내려가는 것을 막는다. **S★ 는 incumbent 점수가 아니라 역대 최고**이므로 incumbent 보다 낮아도 S★−δ 이상이면 바닥은 통과한다(이후 비용 규칙이 판정).

### 4.3 복잡도 인지 수락 (Eq.6, Eq.7)

```
ΔS = Ŝ(H') − Ŝ(H_t),        ΔC = ( Ĉ(H') − Ĉ(H_t) ) / Ĉ(H_t)                                   (6)
```

ΔC 는 **상대 변화율**이다. 이득이 잡음 대역을 넘는 후보(ΔS > δ)에는 다음을 요구한다.

```
ΔC ≤ β0 + β1 · ΔS                                                                               (7)
```

β0 은 이득이 거의 없을 때 허용하는 비용 증가, β1 은 이득에 비례해 늘어나는 허용 폭이다. 둘 다 evolve 집합에서 정하고 이전 평가 내내 고정한다. 특정 구성요소 제거를 요구하지 않고 총 발자국의 성장만 누르므로 Ridge 에 빗댄다. 대역 안(ΔS ≤ δ) 후보는 Eq.17 로 판정한다.

### 4.4 구조 가지치기

Eq.4 가 각 *업데이트*를 희소하게 만든다면 가지치기는 *유지되는 하네스*를 희소하게 만든다. 최근 활성화된 구성요소가 고정 창 안에서 엄격히 양(+)의 이득을 냈는지 추적하고, 그렇지 않은 구성요소를 proposer 에게 삭제 대상으로 알린다. 점수만 보는 진화는 쓸모없어진 장치를 지울 유인이 없다는 문제를 겨냥한다.

## 5. 라운드 수준 정식화 (Appendix C)

### 5.1 라운드 형태 (Eq.8)

```
𝓗_t ∼ P_reg( · | H_t, 𝓕_t, 𝓛_t, b_t, 𝓔_t, 𝓑_t ) ⊆ Ω(H_t),      H_{t+1} = argmax_{H' ∈ 𝓗_t ∩ 𝓐_t} Ŝ(H')        (8)
```

허용 후보가 없으면 `H_{t+1} = H_t`. 𝓕_t 피드백, 𝓛_t 편집 이력, b_t 예산, 𝓔_t 탐색 지시, 𝓑_t 가지치기 대상, 𝓐_t 허용 집합. `t = 0, …, T−1` 을 돌고 `H_0`, `S★ = Ŝ(H_0)`, 사전 보정한 δ 로 시작한다.

### 5.2 제안 쪽 장부 (C.2)

원자 편집 풀 E_t 의 부분집합을 `z_t ∈ {0,1}^{|E_t|}` 로 나타낸다(풀 크기는 라운드마다 다르다).

```
‖z_t‖_0 ≤ b_t                                                                                   (9)

𝓛_t = { (t_i, ℓ_i, h_i, d_i, ΔS_i, ΔC_i, a_i) : i ≤ n_t },      a_i ∈ {0,1}                        (10)

𝒯_t = { ℓ_i : i ≤ n_t },      g_t(ℓ) = max{ ΔS_i : ℓ_i = ℓ,  t − t_i ≤ n_prune },      max ∅ = −∞      (11)

𝒦 = { prompt, control_flow, config, output_plumbing, context_mgmt, client_tool, skill, memory, subagent }    (12)

𝓔_t = (σ_t, 𝒰_t, m_draft),      σ_t = 𝟙[ Ŝ_t − Ŝ_{t−w} ≤ δ ],      𝒰_t = 𝒦 \ 𝒯_t                         (13)

𝓑_t = { ℓ ∈ 𝒯_t : g_t(ℓ) ≤ 0 }                                                                 (14)
```

- 이력은 **편집 단위**다. 편집 n 개를 묶은 후보는 레코드 n 개를 남기고, 모두 같은 ΔS·ΔC·결과를 공유한다. 측정 전에 실패한 후보는 이력에서 빠진다.
- `a_i = 1` 은 그 편집을 담은 후보가 라운드 승자로 채택됐다는 뜻이다. 허용됐지만 더 높은 점수에 진 후보는 0.
- 𝒯_t 는 측정된 편집이 있는 구성요소, g_t(ℓ) 는 가지치기 창 안의 최고 이득, 𝒰_t 는 아직 측정되지 않은 구성요소, m_draft 는 정체 시 예약하는 탐색 슬롯 수다.
- 창 안에 측정이 없으면 g_t(ℓ) = −∞ ≤ 0 이므로 𝓑_t 에 들어간다. proposer 는 𝓑_t 와 해당 구성요소의 기존 채택 편집 목록을 받는다.

### 5.3 선택 쪽 장부 (C.3)

```
𝒦_str = { client_tool, skill, memory, subagent }                                                (15)

ν_t(H') = Σ_{ℓ ∈ 𝒦_str} 𝟙[ ℓ ∈ comp(H')  ∧  N_t(ℓ) = 0 ]                                        (16)

w_s · ΔS − w_c · ΔC + w_n · ν_t(H') > 0                                                        (17)
```

- N_t(ℓ) 는 라운드 t 이전에 ℓ 로 태그된 채택 편집 수, comp(H') 는 후보가 건드린 구성요소 타입 집합이다. ν 는 한 번도 채택된 적 없는 **구조** 타입을 몇 개 새로 건드렸는지 센다. 구조가 아닌 다섯 타입은 보너스가 없다.
- 판정 분기: 바닥(Eq.5)을 넘은 뒤 ΔS > δ 이면 Eq.7, ΔS ≤ δ 이면 Eq.17. Eq.17 에서는 작은 점수 변동만으로는 부족하고, 비용 절감(−w_c ΔC)이나 미시도 구조 메커니즘(w_n ν)이 신용을 보태야 한다.
- 코딩 인스턴스는 **w_s = 0** 이라 대역 안 점수 상승은 신용이 전혀 없다. workspace·엔지니어링은 양의 w_s 를 쓴다.
- 논문은 세 가중치가 Table 5 에 있다고 쓰지만 **실제 Table 5 에는 없다**. 값은 참조 구현 `domains/*/rrsi.json` 에만 있다(코딩 0/15/0.5, workspace 1414/15/0.5, 엔지니어링 244/2/0.5). 02 문서 참조.
- **도메인 가드** `g(H_t, H') ∈ {0,1}`: 코딩·workspace 는 없음(g = 1). 엔지니어링은 incumbent 대비 유효 출력률이 0.03 넘게 떨어지거나 미제출률이 0.02 넘게 오르면 거부한다.
- 최종 선택: 바닥, 해당 비용 분기, 가드를 모두 통과한 후보 중 점수 최고를 고르고 없으면 유지. 그 뒤 `S★ ← max(S★, Ŝ(H_{t+1}))`.

## 6. Algorithm 1·2 의 계산 순서 (Appendix C)

L 번호는 논문 알고리즘의 줄 번호다(코드 주석이 "Algorithm 1 line 1" 처럼 이 번호를 쓴다). 문장은 우리 정리다.

**Algorithm 1 (제안 쪽)** — 입력 H_t, 𝓛_t, t, T, b_min, b_max, w, δ.
L1 incumbent 분석 → 𝓕_t. L2 b_t (Eq.4). L3 σ_t (Eq.13). L4–L5 𝒯_t 와 𝒰_t = 𝒦 \ 𝒯_t. L6 𝓔_t = (σ_t, 𝒰_t, m_draft). L7 𝓑_t (Eq.14). L8 P_reg 로 후보 𝓗_t 샘플. L9 원자 편집마다 구성요소·가설 태그. L10 평가 전 누설 심사를 통과한 후보만 반환.

**Algorithm 2 (선택 쪽)** — 입력 심사된 𝓗_t, (H_t, Ŝ_t, Ĉ_t), S★, δ, k, β0, β1, w_s, w_c, w_n.
L1 𝓐_t ← ∅. L2–L15 후보마다 병렬로: L3 k 회 시행으로 Ŝ', Ĉ'. L4 ΔS, ΔC (Eq.6). L5 ν = ν_t(H') (Eq.16). L6–L10 ΔS > δ 이면 c = [Eq.7], 아니면 c = [Eq.17]. L11 도메인 가드 g. L12–L14 `Ŝ' ≥ S★ − δ ∧ c ∧ g` 이면 𝓐_t 에 추가. L16 𝓐_t 의 점수 최고를 H_{t+1} 로(비면 H_t 유지). L17 S★ 갱신. L18 측정된 편집마다 레코드, 후보가 새 incumbent(≠ H_t)일 때만 a = 1.

판정은 논리곱이라 순서와 무관하다. 참조 구현(`selection.judge`)은 **바닥 → 비용 규칙 → 가드** 순으로 첫 실패 사유를 기록한다.

## 9. 관련 연구 위치 (Appendix B)

Meta-Harness(제약 없는 end-to-end 최적화, evolve 최강·OOD 이득 작음), AHE(관측 기반 진화 루프, 비용 제약 없음·가장 비쌈), TTHE(test-time 다후보 진화와 agentic judge 선택, OOD 에서 H0 아래), HarnessX(타입 있는 모듈형 primitive 조합, OOD 에서 H0 수준). RRSI 는 이들과 탐색 공간은 같게 두고 궤적만 정규화한다는 점에서 갈린다.

## 10. XGEN 관점의 시사점

1. **하네스는 프로그램이다.** 구성요소 단위(𝒦)로 분해되어 있어야 원자 편집·태그·귀속·가지치기가 성립한다. 현재 21-stage 파이프라인은 동작이 stage·strategy·manifest·프롬프트·호스트 코드에 흩어져 있어 이 분해가 어렵다(10·13 문서).
2. **정책은 고정, 비용 단위는 정책 토큰.** ΔC 가 상대 변화라 같은 정책 안에서는 토크나이저 차이가 상쇄된다. 다중 공급자 환경에서는 하네스 계보를 정책별로 두는 것이 자연스럽다(Table 3 도 정책별 독립 진화).
3. **측정 장치는 하네스 밖에 둔다.** 검증기·토큰 집계·결측 시행 처리를 하네스가 건드릴 수 없어야 채점기 게이밍을 막는다(헌법 hard rule 3, critic 규칙 3).
4. **판단의 근거는 기록이다.** 편집 단위 이력, frontier, decisions.json 이 수식의 입력 그 자체다. 측정과 판정을 따로 저장해 재판정이 가능해야 한다.
5. **선택은 비보상적 논리곱이다.** 점수 하나로 다른 실패를 메우지 않는다는 점이 운영 배포 게이트(사람 승인 포함)와 잘 맞는다.
6. **δ 는 실측 보정값이다.** evolve 집합·k·검증기가 바뀌면 다시 재야 한다.

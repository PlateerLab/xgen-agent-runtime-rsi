# 40. 에이전트마다 자기 하네스 — XGEN 안에서 도는 자가 진화

> 이 문서가 geny-rsi 의 운영 구조를 정한다. 원칙은 [30](30-fusion-philosophy.md), 커널·하네스 형식은 [31](31-architecture.md),
> 검증기는 [34](34-evaluation-verifiers.md), 안전은 [35](35-risks-safety-governance.md).
>
> **0.8.0 부터 진화 실행(§2.3·§2.4)은 [41 — 턴 정리](41-turn-consolidation.md)로 바뀌었다.** 진화는 버튼이나 자동 진화 스위치가 아니라
> 턴이 끝날 때마다 돌고, 평가는 사용 기록을 새 질문으로 다시 묻는 대신 그 턴의 실제 환경을 재생한다(Dream-RSI). 하네스가 에이전트의 것이라는
> 원칙(§0·§1)과 계보·되돌리기는 그대로다.

## 0. 한 문장

**XGEN 에서 만든 Agent Geny RSI 는 모두 RSI 파이프라인의 기본값(H0)에서 시작하고, 그 에이전트를 쓰는 사용자의 실제 사용(대화·피드백·
기대 답)을 재료로 RRSI 가 그 에이전트 하나의 하네스를 진화시킨다. 하네스는 에이전트의 것이다.**

RSI 의 강점은 사용자 fit 이다. 같은 모델이라도 에이전트마다 하는 일·사용자·자료가 다르므로 맞는 하네스도 다르다. 그래서 패키지는 H0 만 싣고,
특정 스위트·모델에 맞춘 하네스를 미리 넣지 않는다. 실험(보고서)은 방법론이 동작하는지 재는 것이고, 그 산출물은 운영에 들어가지 않는다.

## 1. 전체 흐름

```
             ┌──────────────────────────── XGEN (에이전트 하나 = workflow 하나) ─────────────────────────────┐
  사용자 ──턴──► Agent Geny RSI 노드 ── GenyRSITurnExecutor ── 커널 + [이 에이전트의 현재 하네스 H_t] ──► 답
             │        │                                                │
             │        │ 궤적 요약(하네스 버전·종료·도구·비용)                    │  처음에는 H0
             │        ▼                                                │
             │   [사용 기록]  ◄── 별점·이슈·코멘트(피드백) · 기대 답(품질평가)      │
             │        │                                                │
             │        ▼ 과제로 만든다(턴 입력 + 판정 기준)                       │
             │   [이 에이전트의 과제]  evolve / heldout                         │
             │        │                                                │
             │        ▼ 진화 실행(사용자가 시작하거나, 과제가 쌓이면)              │
             │   RRSI 라운드: 분석 → 제안 → 심사 → 평가(이 에이전트의 과제) → 판정   │
             │        │                                                │
             │        ▼ 채택(잡음 바닥·비용 규칙·가드)                            │
             │   [이 에이전트의 하네스 계보]  H0 → H1 → H2 …  ─────────────────────┘ 다음 턴부터 H_{t+1}
             └──────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. 구성요소

### 2.1 하네스는 에이전트에 붙는다

- **저장.** XGEN DB 에 에이전트별 하네스 계보를 둔다(`workflow_id`, 버전 sha, 부모, manifest, 참조 파일, 출처 라운드, 판정 수치,
  상태 adopted/rolled_back, 만든 때). 현재 하네스 = 그 에이전트의 마지막 채택 버전. 없으면 H0.
- **턴.** 호스트의 선택 훅 `rsi_agent_harness()` 가 이 턴 에이전트의 현재 하네스(manifest + 파일)를 돌려준다. geny-rsi 는 버전 sha 로
  로컬에 한 번 풀어 두고 쓴다. 고르는 순서: 관리자 고정(`XGEN_RSI_HARNESS_DIR`) → **에이전트 하네스** → 패키지 계열 표(H0) → H0.
- **에이전트와 함께 움직인다.** 복제·고정본은 하네스 계보를 같이 가져간다. 고정본은 그 시점의 하네스로 굳는다(진화하지 않는다).

### 2.2 사용 기록 — 진화의 재료

| 재료 | XGEN 의 출처 | 쓰는 곳 |
|---|---|---|
| 턴 입력·출력 | `execution_io`(입력·출력·상태·토큰·모델) | 과제의 요청과 참조 답 |
| 궤적 요약 | geny-rsi 기록기 → 호스트 훅 `rsi_record(record)` → 에이전트별 저장 | 어느 하네스 버전이 어떻게 끝났나(종료 사유·도구 실패·비용), 분석기 재료 |
| 사용자 피드백 | `user_feedbacks`(별점 1–5, 이슈 유형, 코멘트) | 실패·성공 판단, 판정 기준 |
| 기대 답 | `execution_io.expected_output`(품질평가) | 판정 기준 |
| 사용자가 직접 넣은 과제 | [하네스] 화면 | 판정 기준 |

기록은 기본으로 **구조·점수·비용**만 남긴다(설계 35). 과제가 되는 턴의 입력·출력은 이미 `execution_io` 에 있으므로 따로 복사하지 않는다.

### 2.3 과제 — 사용을 판정 가능한 문제로

과제 하나 = 그 턴의 요청(앞 대화 포함) + 판정 기준 목록. 판정 기준은 결정적 검사(`answer_contains`·`answer_json` …)와 **기준 판정**
`answer_criteria`(판정 모델이 답이 기준을 만족하는지 본다 — RRSI 논문 workspace 인스턴스의 criteria 채점과 같은 방식)를 쓴다.

| 사용 기록 | 만드는 판정 기준 |
|---|---|
| 기대 답이 있다 | "기대 답과 내용이 같다"(기준 판정, 참조 = 기대 답). 짧은 값이면 결정적 검사도 |
| 낮은 별점(≤2) + 이슈·코멘트 | "이 문제가 없어야 한다: <이슈 유형> — <코멘트>" (기준 판정) |
| 높은 별점(≥4) | "받아들여진 답의 요점을 빠짐없이 담는다"(기준 판정, 참조 = 그때의 답) — 회귀 방지 |
| 사용자가 넣은 과제 | 사용자가 쓴 기준 그대로 |

판정 모델과 판정 기준은 **하네스 밖**이다(커널·도메인 소유 — 하네스는 실행 중 기준을 보지 못한다). 과제는 해시로 evolve/heldout 에 나눈다.

### 2.4 진화 실행 — 에이전트 하나의 RRSI

- **시작.** 사용자가 [하네스] 화면에서 시작하거나, 에이전트가 자동 진화를 켰다면 새 과제가 일정 수 쌓였을 때.
- **정책 π** = 그 에이전트의 모델(XGEN 에 등록된 LLM·자격). **역할 모델**(분석·제안·검토·요약·판정) = XGEN 에 등록된 LLM 중 관리자 설정, 없으면
  에이전트 모델.
- **평가 환경.** 과제마다 독립 작업 공간에서 그 에이전트의 설정(시스템 프롬프트·출력 스키마)으로 턴을 돈다. 기억 쓰기·작업 예약·앱 배포·외부로
  나가는 도구처럼 부작용이 있는 것은 평가에서 막는다(평가가 사용자의 실제 데이터·외부 시스템을 건드리지 않게). 어떤 도구를 평가에 열지는
  호스트가 정한다(평가 환경 훅).
- **판정.** RRSI 그대로 — δ 보정, 잡음 바닥, 비용 규칙, 띠 안 규칙, 읽히지 않은 편집 가드, 환경 단정 금지. 채택이 나오면 그 에이전트의 다음
  하네스 버전이 된다(자동). 모든 판정 입력이 남고, 사용자는 화면에서 이전 버전으로 되돌릴 수 있다.
- **계보는 에이전트마다.** 한 에이전트의 진화는 다른 에이전트에 영향을 주지 않는다.

### 2.5 Dream-RSI

진화 실행의 평가 시행은 그대로 그 에이전트의 재생 world 가 된다(과제마다 발견 트리). 과제를 여러 갈래로 풀어 보는 탐색(검증기가 있는 과제)에서 쓰는
탐색 정책 π_E 를 그 에이전트의 world 로 Dream 사이클이 고친다. 운영 대화 턴은 검증기가 없어 한 경로로 돈다.

### 2.6 화면 — Agent Geny RSI 상세의 [하네스] 탭

- 현재 하네스: 버전, H0 대비 바뀐 것(구성요소·파라미터·스킬 문서).
- 계보: 버전마다 채택 라운드·ΔS·ΔC·판정 사유, [되돌리기].
- 과제: 사용 기록에서 만든 과제(출처 턴·판정 기준), 넣기·빼기, 직접 추가.
- 진화: [진화 시작]·[중지], 진행 상황(라운드·후보·판정), 자동 진화 켜기.

## 3. 무엇을 하지 않나

- 패키지에 특정 모델·스위트에 맞춘 하네스를 싣지 않는다. 모든 에이전트는 H0 에서 시작한다.
- 한 에이전트의 사용 기록으로 다른 에이전트의 하네스를 바꾸지 않는다.
- 사용자 데이터(기억 내용·파일)·권한·안전장치를 하네스가 바꾸지 않는다(커널 소유).
- 평가가 실제 외부 시스템이나 사용자의 기억을 바꾸지 않는다.

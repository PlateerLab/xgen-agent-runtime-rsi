# 41. 턴 정리 — 턴마다 Dream-RSI × RRSI 로 에이전트의 하네스를 고친다

> 근거: Dream-RSI(arXiv 2609.14858) §3·§5.1·부록 B, RRSI(arXiv 2609.24972) §3·부록 C, 융합 철학 [30](30-fusion-philosophy.md)
> (P5·P7·P10), 에이전트별 진화 [40](40-agent-self-evolution.md). 이 문서는 40 의 "진화 실행(§2.4)"을 **턴마다 도는 정리**로 바꾼다.

## 0. 한 문장

**에이전트의 턴 하나하나가 Dream-RSI 의 온라인 실행이고, 그 턴의 실제 환경 응답이 재생 세계로 남으며, 턴이 끝나는 즉시
[정리]가 그 세계들 위에서 RRSI 라운드 하나를 재생으로 돌려(도구를 다시 실행하지 않는다) 채택된 하네스를 바로 다음 턴에 쓴다.**

## 1. 두 논문은 언제 정리하는가 (원문 확인)

| | 갱신 단위 | 실행 중 | 갱신 시점 |
|---|---|---|---|
| RRSI | 라운드 t (evolve 집합 전체 × k 실행 → 분석 → 제안 → 평가 → 선택) | 하네스 고정 | 라운드마다. 가지치기 𝓑_t 도 매 라운드 제안 직전(알고리즘 1 의 7행), 최근 n_prune 라운드 증거 |
| Dream-RSI | 바깥 반복 t (온라인 실행 1회 → 기록을 세계 풀에 더함 → 꿈꾸기 → 배치) | "The policy code stays fixed throughout the rollout" | 온라인 실행이 끝날 때마다 |

에이전트 운영에서 **온라인 실행 하나 = 턴 하나**다. 그래서 두 논문의 갱신 경계는 **턴과 턴 사이**다. 턴 안에서는 하네스를 바꾸지
않고, 턴이 끝나면 정리하고, 다음 턴이 정리 결과를 쓴다. 대화(Interaction)는 바뀌지 않는다 — 하네스는 턴이 시작할 때마다
호스트 훅 ``rsi_agent_harness()`` 로 다시 읽힌다.

## 2. 대응 — Dream-RSI 의 철학을 하네스 정리로

Dream-RSI 의 핵심은 "완료된 실행 기록이 곧 재생 시뮬레이터이고, 대안 정책을 그 위에서 평가하면 비싼 온라인 실행 없이 즉시 피드백을
얻는다"이다. 운영 대화 턴에는 검증기가 있는 분기 탐색(π_E)이 열리지 않으므로(설계 30 P6), 그 철학을 **하네스 후보 평가**에 적용한다.

| Dream-RSI | 턴 정리 |
|---|---|
| 온라인 실행(현재 정책 고정) | 사용자의 턴(현재 하네스 고정) |
| 발견 트리 𝒯_t (노드 = 시도 + 저장된 결과) | 턴 세계: 모델이 본 입력(시스템 조각·앞 대화·입력·기억 검색 결과·시각), 도구 목록, **도구 호출마다 실제 결과** |
| 𝓗_t = 𝓗_{t−1} ∪ {𝒯_t} | 에이전트의 세계 풀에 턴마다 하나씩 더한다 |
| 재생: 고른 노드의 저장된 자식을 결정적으로 돌려준다 | 재생: 후보 하네스로 같은 턴을 다시 조립해 돌리되, 도구 호출은 **기록된 결과**를 돌려준다(실제 도구 실행·부작용 없음). 모델 응답만 새로 받는다 |
| 기록 밖 자식 → Child = ∅ | 기록에 없는 도구 호출 → "기록된 결과 없음" (∅). 재생은 계속되고, 지원 밖 호출 수를 센다 |
| 평가기 점수 s_v | 사용자 신호로 만든 판정 기준을 재생 답에 채점(기대 답, 별점·이슈·코멘트, **다음 사용자 메시지의 반응**) |
| 정책 개발 에이전트가 M 개 수정안 | RRSI 제안자 m 개(편집 예산 b_t·증거 이력·탐색 지시·가지치기) + 누설 검토 |
| argmax V^m (현재 정책 포함, 재생 위 비퇴화) | RRSI 선택(현재 하네스 유지 포함): 잡음 바닥, 비용 규칙, 띠 안 규칙, 가드 |
| 재배치 → 다음 온라인 실행 | 채택 → **바로 다음 턴** |
| 이력을 방향 지침으로 프롬프트에 넣지 않는다(§5.1) | 대화 요약·교훈을 하네스 프롬프트에 주입하는 편집은 검토자가 거절한다(대화 특화 내용 = 누설). 이력은 제안자의 증거로만 쓴다(설계 30 P10) |
| prefix-only, 기록 특화 값 복사 금지 | 재생 결과·판정 기준은 하네스가 보지 못한다. 대화의 사실·이름·답을 하네스에 쓰면 거절 |

## 3. RRSI 를 턴 단위로

| RRSI | 턴 정리 |
|---|---|
| 라운드 t | 라운드를 돌린 정리 하나. t 는 에이전트마다 이어지는 번호(실행마다 0 부터가 아니다) |
| D_evolve | 이번 라운드의 평가 세계 W_t: 신호가 있는 세계 중 새 신호가 붙은 것 → 지금 하네스가 틀리는 것 → 지키라는 신호가 있는 것 순, 최대 N_eval |
| Ŝ, Ĉ (Eq.3) | 세계마다 k 시행의 판정 점수·정책 토큰. 지금 하네스로 기록된 턴은 그 자체가 지금 하네스의 시행 하나다(on-policy) |
| δ (§2.4) | 지금 하네스의 W_t 시행으로 보정(시행 부트스트랩), 하한 = 판정 한 칸 |
| S★ | 세계 풀이 턴마다 바뀌므로 같은 W_t 위의 지금 하네스 점수 |
| 𝓛_t | 에이전트의 편집 이력 — 정리 사이에 이어진다(증거 기반 신용, 가지치기 창) |
| b_t (Eq.4) | t 를 지평 T 에서 자른다(t ≥ T 면 b_min) |
| σ_t (Eq.13) | 지난 w 라운드 동안 채택된 ΔS 합이 δ 이하면 정체 |
| 𝓑_t (Eq.14) | 이어진 이력의 최근 n_prune 라운드 |
| 정확 경계 조기 종료(설계 33 §4) | 그대로 — 바닥에 못 미침이 확정되면 남은 재생을 돌리지 않는다 |

## 4. 언제·얼마나 빨리

턴이 끝나면 호스트가 그 에이전트의 정리를 **곧바로 백그라운드로** 시작한다. 에이전트마다 하나만 돌고, 도는 동안 끝난 턴은
대기 표시만 남겨 끝난 뒤 한 번 더 돈다(겹치지 않는다). 다음 턴은 시작 시점의 현재 하네스를 쓴다 — 정리가 끝나기 전에 시작한
턴은 이전 하네스로 끝까지 돌고(턴 안에서는 바꾸지 않는다), 그다음 턴부터 새 하네스다.

| 단계 | 언제 | 비용 |
|---|---|---|
| 0. 세계 저장 | 매 턴 | 없음(턴이 이미 만든 기록) |
| 1. 신호 | 매 턴(같은 대화에 앞 턴이 있으면) | 판정 모델 1회 — 이번 사용자 메시지가 앞 턴 답에 대한 정정·불만·수용인지, 무엇이 필요했는지 |
| 2. 라운드 | 고칠 것을 말하는 새 신호(정정·불만·낮은 별점·이슈·기대 답)가 있고 지금 하네스가 그 기준을 틀릴 때. 가지치기 대상 𝓑_t 는 라운드의 제안 입력이다(라운드를 열지 않는다) | 분석 1 + (제안 + 검토) × m + 재생(병렬) + 판정 |
| (그 밖) | 고칠 근거가 없으면 정리는 기록만 하고 끝난다 | — |

시간을 줄이는 장치: 도구를 다시 실행하지 않는 재생(Dream), 지금 하네스의 기록 턴을 시행으로 재사용, 하네스 버전별 재생 답
캐시(기준이 늘면 답은 두고 다시 채점), 세계 상한 N_eval, 병렬 재생, 정확 경계 조기 종료, 분석기는 디제스터 없이 한 번 호출.

## 6. 경계

- 판정 모델·판정 기준·재생기·세계는 하네스 밖이다(커널·호스트 소유). 하네스는 실행 중 기준을 보지 못한다.
- 세계는 그 에이전트의 XGEN 저장소에만 남는다(호스트가 개수·크기를 자른다). 다른 에이전트의 진화에 쓰지 않는다.
- Claude Code·Codex 처럼 루프를 소유하는 공급자는 재생할 수 없다(커널이 루프를 갖지 않는다) — 세계를 기록하지 않고 정리도 건너뛴다.
- 기록 밖 행동은 ∅ 로 처리하므로, 새 도구를 많이 쓰게 하는 편집은 재생에서 불리하다. 새 방향은 채택된 뒤의 실제 턴이 다음
  세계가 되어 검증된다(Dream 의 재배치 → 새 기록).

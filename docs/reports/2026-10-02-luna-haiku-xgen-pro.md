# 천장 아래 모델에서 geny vs geny-rsi — gpt-6-luna · claude-haiku-4-5 × xgen-pro (2026-10-02)

> 1차 보고서([2026-10-01](2026-10-01-geny-vs-geny-rsi.md))는 gpt-6-sol·claude-sonnet-5 가 천장(0.9~1.0)이라 하네스 개선을 가릴 수 없다고
> 결론냈다. 이번에는 **천장 아래 모델**과 **더 어려운 스위트(xgen-pro)** 로 다시 쟀다.
> 원자료: [data/2026-10-02.json](data/2026-10-02.json)(`experiments/summarize.py`, 대화 내용·답 제외).

**요약**

- **갈아끼워도 잃지 않는다.** 진화 전 geny-rsi(H0)는 두 모델·두 분할 모두 기존 runtime(geny)과 점수 차이가 잡음 안이다
  (luna 0.919 vs 0.906, haiku 0.826 vs 0.810 — evolve, k=2).
- **luna: RRSI 가 evolve 점수를 올렸지만 보류 분할로 옮겨 가지 않았다.** 5라운드에서 2번 채택, evolve 0.919 → 0.948. 판정에 쓰지 않은
  보류 분할(k=4)에서는 H\* 0.911 vs H0 0.907 vs geny 0.916 — 잡음 안이고 토큰은 H0 보다 26% 많다. **그래서 패키지에 넣지 않는다.**
- **haiku: 같은 점수대에서 비용을 줄이는 편집이 나왔다.** 라운드 0 채택 편집은 점수 띠 안(−0.018)에서 토큰 −10.6%. 무효 처리한 앞선 실행에서는
  점수 그대로 토큰 −45.8% 편집도 나왔다(아래 §6, 환경 단정 때문에 무효). haiku 진화는 2라운드 도중 **API 크레딧 소진으로 멈췄고**, 재개 후 갱신한다.
- **측정과 가드가 실제로 일을 했다.** 비용만 늘린 후보 7/10 을 비용 규칙이 거절했다(luna). 실측 중에 세 가지 결함을 찾아 막았다 — 빈 분석,
  평가 환경을 사실로 박는 편집, 크레딧 장애 시 누락 기록(§8).
- **Dream-RSI: 탐색 시도 −36% 를 찾았지만 비용은 줄지 않아 승격하지 않았다.** gpt-6-sol 이 개발한 luna 탐색 정책이 같은 최고점을 시도 72 → 46 으로
  찾았지만 정책 토큰은 +0.16% — 확인 판정이 거절했다.
- **결론:** 지금 Agent Geny RSI 는 모든 모델에서 H0(= Agent Geny 와 같은 동작)로 돈다. geny-rsi 가 "더 강하게" 달성한 것은 아직 **점수**가 아니라
  **측정된 변경 관리** — 손해 보는 변경을 자동으로 거르고, 채택 근거를 남기고, 운영에 해로운 편집을 막는 것 — 와 haiku 의 비용 절감 후보다.

## 1. 왜 다시 쟀나

1차 실험에서 gpt-6-sol 은 xgen-hard 에서도 0.99, sonnet-5 는 xgen-core 만점이었다. 하네스가 나아질 여지가 없으면 RRSI 는 잡음만 재게 된다.
이번에는 (1) 가볍고 싼 모델 두 개 — **gpt-6-luna**(OpenAI), **claude-haiku-4-5**(Anthropic) — 와 (2) 하네스가 결과를 가르는 지점을 더 세게 넣은
**xgen-pro** 스위트로 쟀다.

## 2. xgen-pro 스위트

8범주 × 4과제(evolve 24 · heldout 8 · smoke 2). 정답은 전부 코드로 계산하고, 과제마다 **오라클 만점·빈 답 0.5 이하**를 테스트로 고정했다.

| 범주 | 노리는 지점 |
|---|---|
| 회의록 종합 | 회의록 20건(7만 자+)에서 결정·철회·담당 변경·기한 연기·정정 문서까지 추적, 초안은 무시 |
| 장부 마감 | 입금·청구서·일별 환율 대조, 참조 표기 정규화, 원 단위 반올림, 완납·부분·초과·미수 판정 |
| 대량 변환 | 연락처 100행+ 정규화·중복 제거·정렬을 CSV 한 파일로(긴 정확한 출력) |
| 설정 이관 | 서비스 24개, `[server]`·`[db]` 의 같은 키 중 한쪽만 바꾸기, 동결 서비스 보존, 포트 재배정 |
| 정책 우선순위 | 개정 12건(철회 3, 본부·직급 범위)·개인 예외 3건, 질문 12개 |
| 일정 퍼즐 | 회의 10~11개 · 방 3 · 교시 4, 참석자 겹침 금지, 정답 하나 |
| 검색·복구 | 문서 56개+(개정판 포함 파일 140개+), 대상 12개를 내용으로 찾고 최신 개정판 고르기(미끼 언급·임시 사본 제외) |
| 감사 정정 | 판매 140행+, 동료 보고서 16항목 중 틀린 8개만 고치기 |

**난이도 보정.** heldout 8과제·1회 파일럿으로 세 번 키웠다. luna 0.896(v1) → 0.934(v2, 범주 하드닝) → 0.932·0.908(v3, 규모 확대).
v3 에서도 luna 는 설정·정책·검색에서 만점이고, 대량 계산·긴 출력 범주(장부·연락처·감사)에서 무너진다. haiku 는 거의 모든 범주에 여지가 있다.
만점 범주는 "하네스가 기존 능력을 깨뜨리지 않는가" 를 재는 역할을 한다.

## 3. 방법

- **엔진.** geny = 21-stage 엔진. rsi 안의 사본(`xgen_rsi.base`)으로 돌렸고, 사본은 xgen-agent-runtime 4.80.0 과 **519개 중 517개 파일이
  바이트 단위로 같다**(나머지 2개는 버전 표기·docstring 경로, `COPY.json`). geny-rsi = 커널 + 하네스(H0 또는 진화본).
- **정책.** gpt-6-luna, claude-haiku-4-5. 평가 호스트는 파일 도구 5종(Read·Write·Edit·Glob·Grep)만 준다 — **코드 실행 도구가 없다**(§8-2 참고).
- **RRSI 역할 모델.** 제안·검토·분석·요약: luna 진화는 gpt-6-sol, haiku 진화는 claude-sonnet-5(약한 정책의 하네스를 강한 제안자가 고친다).
  T=5 라운드, 라운드당 후보 2개, evolve 24과제 × k2.
- **잡음 바닥 δ.** 기준 하네스를 두 번 평가해 보정(z=2): luna 0.025, haiku 0.032. 두 번째 기준 평가는 실험 1 의 geny 시행이다 — 두 엔진이 같은
  요청을 보낸다는 것은 1차 보고서 실험 2(재생 동등성)로 실측했다.
- **지표.** S = 검사 가중 평균 보상, ± = 과제 평균의 표준오차. 토큰 = 시행당 외부 usage(입력+출력). RRSI 의 Ĉ 도 이 값이다.

  상향(`prune_over_tokens`). evolve S 0.919 → 0.948(+0.029, δ 위).
- 분석기가 찾은 실패 유형은 연락처 내보내기 누락·순서, 입금 대조 오류, 감사 정정의 불필요 항목, 너무 이른 "불가능" 결론, 뒤 회의의 철회 미반영이었다.
  채택된 편집은 첫째(누락)와 다섯째(긴 문서에서 앞 내용이 잘려 나가는 것)를 겨냥한다.

## 6. 실험 3 — 보류 분할 최종 비교 (gpt-6-luna, heldout 8과제 × k4)

| | S | 시행당 토큰 | 초 |
|---|---|---|---|
| geny | 0.916 ±0.071 | 43,707 | 39 |
| geny-rsi H0 | 0.907 ±0.074 | 50,619 | 43 |
| geny-rsi H\* | 0.911 ±0.067 | 63,576 | 44 |

과제별 짝 차이(과제 평균): H\*−H0 +0.018 ±0.036, H\*−geny −0.015 ±0.050, H0−geny −0.033 ±0.037. 범주별로는 H\* 가 장부(+0.19)·감사(+0.13)에서
H0 보다 높고 일정(−0.15)에서 낮다 — 과제가 범주당 하나라 한 과제의 성패가 크게 흔들린다.

**해석.** evolve 의 +0.029 는 보류 분할로 옮겨 가지 않았고, 비용은 늘었다. 채택 두 건이 모두 "띠 안" 규칙(잡음 안의 이득 + 비용·새 구조 가점)으로
들어왔다는 점이 이유로 보인다 — 어느 편집도 혼자서는 δ 를 넘지 않았다. 그래서 이 H\* 는 **패키지에 넣지 않는다**(README 의 기준: 잡음 이상의 이득
또는 같은 점수에서 비용 감소가 보류 분할에서 확인될 것).

## 8. 실측에서 찾아 고친 것

| 결함 | 어떻게 드러났나 | 고친 것 |
|---|---|---|
| **분석기가 빈 보고서를 냄** — 궤적이 긴 스위트에서 요약을 계속 더 요청하다 턴 상한(30)에 닿아 실패 유형 0개로 끝남. 제안자는 분석 없이 편집했다 | luna 라운드 0 로그 `top modes: []` | 남은 턴을 알려 주고, 상한에서는 요약 대신 **보고를 강제**한다. 분석기 대화 기록을 남긴다. 그 라운드는 무효로 하고 다시 돌렸다(이후 13턴 만에 실패 유형 5개) |
| **평가 환경을 사실로 박는 편집이 채택됨** — "이 작업 공간에는 코드 실행 도구가 없다, 스크립트는 실행되지 않는다". 평가 호스트에는 맞지만 XGEN 운영(샌드박스 Bash)에서는 틀리다. 그 편집은 점수 그대로 토큰 −45.8% 를 냈다 | haiku 라운드 1 채택 편집 검토 | 검토자·헌법 규칙 11: 환경에 무엇이 있다·없다는 단정 금지, 도구 지침은 "목록에 있으면 … 없으면 …" 조건부로만. 그 실행은 무효로 하고 처음부터 다시 돌렸다(이후 채택 편집은 모두 조건부) |
| **크레딧 장애 시행이 0점 누락으로 쌓임** | haiku 라운드 1 평가 중 400 오류 | 진화를 멈추고 장애 시행 22개를 지워 재개 때 다시 돌게 했다 |

이전에 고친 결함(측정되지 않은 편집 채택 → 읽힌 파라미터 가드, 0.2.0)은 이번 실행에서 다시 나오지 않았다.

## 9. 무엇을 더 강하게 달성했나 — 그리고 아직 못 한 것

| | 실측으로 보인 것 | 아직 보이지 못한 것 |
|---|---|---|
| 교체 | 진화 전 geny-rsi 는 두 모델·두 분할에서 runtime 과 같은 성능(차이 δ 안) | — |

## 10. 한계

- **평가 환경과 운영의 차이.** 평가 호스트는 안전 때문에 코드 실행 도구를 주지 않는다. XGEN 운영의 Agent Geny 는 샌드박스 Bash 가 있어, 장부·연락처·
  감사처럼 대량 계산 범주는 운영에서 훨씬 쉽다. 이번 숫자는 "코드 실행 없는 환경" 의 숫자다.
- **표본.** 보류 분할은 범주당 1과제(8과제)라 한 과제의 성패가 평균을 크게 움직인다(± 0.07). 0.02~0.03 의 차이는 가리기 어렵다.
- **띠 안 채택.** RRSI 의 띠 안 규칙(새 구조 가점 포함)은 잡음 안의 이득도 채택한다. 탐색에는 유익하지만, 운영 반영 기준은 보류 분할 확인으로 따로 둔다.
- **선택 규칙.** 자격 있는 후보 중 점수 최대를 고른다(논문 Algorithm 2). haiku 무효 실행 라운드 0 에서 비용 −30.5% 후보가 점수 0.003(잡음 안) 차이로 졌다.
- **haiku 미완.** 진화 2/5 라운드, 보류 분할·Dream 미실행(크레딧).

# geny vs geny-rsi — 상세 비교 보고서 (2026-10-01)

> 대상: 기존 엔진 **geny**(xgen-agent-runtime 의 21-stage 파이프라인)와 새 엔진 **geny-rsi**(이 저장소의 커널 + 하네스 + RRSI·Dream-RSI).
> 모델: **gpt-6-sol**(OpenAI, Responses API)·**claude-sonnet-5**(Anthropic). 실험 날짜: 2026-10-01.
> 원자료 요약: [data/2026-10-01.json](data/2026-10-01.json) — `experiments/summarize.py` 가 만든다(대화 내용·답 제외).

## 1. 무엇을 비교했나

| 이름 | 무엇 |
|---|---|
| **geny** | xgen-agent-runtime 의 기존 21-stage 엔진(`AgentTurnExecutor`) |
| **geny-rsi H0** | 이 저장소의 커널 + 시작 하네스 H0(기존 운영 동작을 구성요소로 옮긴 것). 진화 전 |
| **geny-rsi H\*** | H0 에서 RRSI 로 진화시켜 채택된 하네스(모델마다 하나) |
| **π₁ / portfolio / π\*** | 라이브 탐색 정책 — 논문의 초기 정책(병렬 정련), 손으로 쓴 portfolio, Dream 사이클이 승격한 정책 |

질문은 네 가지다.

1. **갈아끼울 수 있나** — 같은 정책·같은 입력에서 geny-rsi H0 는 geny 와 같은 일을 하는가(실험 1·2·3).
2. **같은 비용으로 같은 점수인가** — 점수·토큰·시간(실험 1·3).
3. **스스로 나아지나** — RRSI 로 하네스를 진화시키면 보류 분할에서 점수·비용이 나아지는가(실험 4).
4. **탐색 계산을 더 잘 쓰나** — Dream-RSI 사이클이 같은 최고점을 더 적은 탐색으로 찾는 정책을 고르는가(실험 5).

## 2. 방법

**공통 조건**
- 런타임: 두 엔진 모두 xgen-agent-runtime **4.78.0** wheel. 공급자 계층(클라이언트·재시도·Responses API)도 같다.
- 호스트: `EvalHost`(LocalHost). 시행마다 독립 작업 공간, 내장 파일 도구 5종(Read·Write·Edit·Glob·Grep)은 그 안으로만 쓴다.
  시작 파일의 수정 시각은 경로 순으로 고정한다(Glob 의 결과 순서를 결정적으로 — §4 참조).
- 정책 설정: 모델 기본값(temperature 0.7 요청, 추론 모델은 공급자 규칙대로), 기억·자기진화 끔, 과제별 반복 상한(xgen-core 기본·xgen-hard 30).
- 키: 실험자가 넘긴 키를 정책 JSON 으로만 전달(저장소·기록·frontier 에 쓰지 않음).

**스위트(둘 다 이 저장소에 내장, 8범주 × 4과제, evolve 24 · heldout 8 · smoke 2)**
- `xgen-core`: 과제마다 규칙이 하나인 업무 과제(CSV 집계·문서 필드 추출·주간 보고 종합·설정 수정·형식 계약·계산·한국어 회의록·파일 이름 복구).
- `xgen-hard`: 하네스가 영향을 주는 지점을 겨냥한 과제.
  - 양: 주문 90행+, 설문 55행+, 고객 70행+.
  - 규칙 문서: 정정 행, 상태, 표기 정규화, 반품, 부가세 포함 합계, 중복 응답·고객.
  - 함정: 출장일 뒤 시행되는 부칙, 연기된 일정, 두 번째 보류 항목, 조건부 변경, 폐기본·지난 분기 파일.
  - 그 밖에 두 단계 정합성, 스키마 준수, 상대 날짜.
- 정답은 전부 코드로 계산한다. 과제마다 **오라클 만점·빈 답 0.5 이하**를 테스트로 고정한다(검증기 자체를 검증).

**지표**
- **S** = 검사 가중 평균 보상(통과 검사 / 전체, 가중치 = 검사 수 — RRSI Eq.3). 누락(인프라 실패)은 r 0·분모 포함. ±는 과제 평균의 표준오차.
- **토큰** = 시행당 외부 usage(입력 + 출력, 두 엔진이 같은 정의로 내는 값). RRSI 의 Ĉ 는 geny-rsi 원장의 정책 토큰 c(τ)(모든 호출)다.
- **시간** = 시행당 벽시계 초(공급자 지연이 대부분).

## 3. 실험 1 — xgen-core: geny vs geny-rsi H0

조건마다 시행 64(evolve 24 × k2 + heldout 8 × k2), 누락 0.

| 모델 | 분할 | geny S | geny-rsi S | geny 토큰 | geny-rsi 토큰 | geny 초 | geny-rsi 초 |
|---|---|---|---|---|---|---|---|
| gpt-6-sol | evolve | 0.9189 ±0.030 | 0.9189 ±0.030 | 3,224 | 3,270 | 5.3 | 5.0 |
| gpt-6-sol | heldout | 0.9143 ±0.054 | 0.9143 ±0.054 | 3,663 | 3,477 | 5.6 | 5.5 |
| claude-sonnet-5 | evolve | 1.0000 | 1.0000 | 6,807 | 7,606 | 6.5 | 6.7 |
| claude-sonnet-5 | heldout | 1.0000 | 1.0000 | 7,281 | 7,467 | 7.2 | 6.5 |

- 점수는 네 조건 모두 **같다**. gpt-6-sol 의 실패는 두 엔진에서 똑같이 회의록 과제의 "담당자·기한" 검사에서 났다(모델 쪽 약점, 엔진 무관).
- 토큰 차이는 방향이 섞여 있다(+1.4%, −5.1%, +11.7%, +2.6%). 호출 한 번짜리 과제에서는 두 엔진이 거의 같다(예: sonnet-5 계산 과제 2,550 vs 2,552).
  차이는 호출 수가 흔들리는 다단계 과제(주간 보고·파일 복구)에 몰린다. 예를 들어 모델이 첫 탐색을 `Glob("reports/**")` 로 하면 파일이 안 잡혀 한두 번 더 찾는다(두 엔진 모두).
  같은 응답에서도 엔진이 다르게 행동하는지는 실험 2 가 결정적으로 답한다.
- sonnet-5 는 xgen-core 에서 만점이라 개선 여지가 없다(천장) → 실험 3·4 는 xgen-hard 로 한다.

## 4. 실험 2 — 결정적 재생 동등성

**방법**
1. geny 로 과제를 한 번 실제로 돌리며 공급자 응답을 순서대로 녹음한다(생각 블록·서명 포함).
2. 같은 응답을 각본처럼 내는 클라이언트로 geny 와 geny-rsi 를 다시 돌린다. 도구는 새 작업 공간에서 실제로 실행한다.
3. 두 엔진이 공급자에 보낸 요청(시스템·메시지·도구·모델 설정)을 **호출마다** 비교한다. 정규화는 시각과 작업 공간 경로뿐이다(`experiments/replay_equivalence.py`).

| 모델 | 과제 | 모델 호출 | 같은 요청 | 같은 호출 수 | 같은 답 | 같은 usage | 같은 점수 |
|---|---|---|---|---|---|---|---|
| claude-sonnet-5 | 32 | 81 | **81/81** | 32/32 | 32/32 | 32/32 | 32/32 |
| gpt-6-sol | 32 | 77 | **77/77** | 32/32 | 32/32 | 32/32 | 32/32 |

- 다단계 과제 48개(호출 2~8번)에서도 두 엔진의 요청은 바이트 단위로 같다. sonnet-5 의 생각 블록·서명과 gpt-6-sol 의 Responses API 추론 항목을 포함한다.
- 첫 시도(모델 호출 155번)에서는 9번이 갈렸다. 원인은 엔진이 아니라 **환경의 비결정성**이었다. Glob 은 수정 시각순으로 정렬하는데, 과제 파일을 순식간에 쓰면 수정 시각이 겹쳐 결과 순서가 실행마다 달라진다.
  작업 공간을 만들 때 수정 시각을 고정하자 158/158 이 같아졌다. 이 고정은 평가 전체에 적용된다(재현성 향상).
- 결론: **같은 응답이 오면 geny-rsi H0 는 geny 와 같은 요청을 보낸다.** 실험 1·3 의 토큰·시간 차이는 모델 표본 편차와 공급자 지연이다.

## 5. 실험 3 — xgen-hard: geny vs geny-rsi H0

조건마다 시행 64(evolve 24 × k2 + heldout 8 × k2), 누락 0.

| 모델 | 분할 | geny S | geny-rsi S | geny 토큰 | geny-rsi 토큰 | geny 초 | geny-rsi 초 |
|---|---|---|---|---|---|---|---|
| gpt-6-sol | evolve | 0.9886 ±0.011 | 0.9924 ±0.007 | 8,721 | 9,113 | 12.3 | 11.8 |
| gpt-6-sol | heldout | 1.0000 | 0.9943 ±0.009 | 9,421 | 9,487 | 12.5 | 13.0 |
| claude-sonnet-5 | evolve | 0.8996 ±0.034 | 0.9053 ±0.044 | 19,914 | 20,498 | 43.8 | 46.1 |
| claude-sonnet-5 | heldout | 0.8295 ±0.114 | 0.8977 ±0.062 | 18,402 | 22,923 | 54.2 | 57.8 |

범주별 평균 보상(evolve, geny / geny-rsi). 표에 없는 범주는 두 모델·두 엔진 모두 1.0 이다.

| 범주 | gpt-6-sol | claude-sonnet-5 |
|---|---|---|
| 설문 두 단계 파이프라인 | 0.857 / 0.905 | 0.714 / 0.762 |
| 규정 질의(부칙) | 1.0 / 1.0 | 0.917 / 0.933 |
| 규칙 문서 주문 집계 | 1.0 / 1.0 | 0.538 / 0.538 |

- 두 엔진의 점수 차이는 모두 표준오차 안이다. 가장 커 보이는 sonnet-5 heldout(0.83 vs 0.90)은 주문 집계 과제 하나에서만 났다(geny 0/2 성공, geny-rsi 1/2 성공).
  그 과제는 성공하면 1.0, 실패하면 0.08 로 갈리므로 k=2 에서는 이런 차이가 쉽게 난다. 실험 4 의 최종 비교에서 k=4 로 다시 쟀다.
- sonnet-5 의 주문 집계 실패는 두 엔진에서 같은 모양이다. 응답이 출력 상한(8,192 → 재시도 16,000 토큰)에 걸려 쓸 내용이 남지 않고, report.json 없이 빈 답으로 끝난다(약 160초).
  모델이 90~110행을 글로 직접 계산하려 해서 생긴다. 하네스가 다룰 수 있는 지점이다(파일에 중간 결과를 나눠 쓰기, 출력 설정, 잘린 응답 뒤 이어 쓰기).
- xgen-hard 는 의도대로 천장을 낮췄다. 특히 sonnet-5 는 evolve 0.90, heldout 0.83~0.90 이다. gpt-6-sol 은 xgen-hard 에서도 0.99 근처라 점수가 오를 여지가 작다.

## 8. 검토와 실측에서 찾아 고친 결함

공개 전 코드 검토(읽기 전용 감사)와 실제 모델로 돌리면서 드러난 결함이다. 모두 고쳤고 회귀 테스트를 붙였다.

| 결함 | 어떻게 드러났나 | 고친 것 |
|---|---|---|
| 런타임 4.77·4.78 의 변경(끝나지 못한 턴의 기억 기록, 턴 맥락 주입 자리)이 RSI 커널에 빠짐 | 런타임 diff 대조 | 턴 맥락 주입은 런타임 함수를 직접 부르고, 끝나지 못한 턴 기록은 런타임 함수 그대로. 두 엔진 동등성 테스트 추가(이식을 빼면 실패함을 확인) |
| 재시도를 다 쓴 공급자 오류(`[ERROR] …`)가 누락이 아니라 부분 점수로 채점됨 | 코드 검토 + 실측 | 누락(r 0·분모 포함)으로 판정. 유효성 게이트·재측정이 본다. 누락 시행의 토큰은 Ĉ 에서 뺀다 |

| 결과·이력 파일이 원자적으로 쓰이지 않아, 크래시 후 재개가 막힘 | 코드 검토 | tmp + rename. 읽을 수 없는 결과는 다시 돌리고, 잘린 마지막 이력 줄은 무시 |

| 설정의 모르는 키·역할 블록의 자격증명이 frontier.json 에 기록됨 | 코드 검토 + 실측 | 설정 덤프에서 키·토큰류 값 가림 |

| 역할 LLM 이 비동기 클라이언트를 캐시해 여러 루프·스레드에서 재사용 → "Connection error" | **실제 진화 실행**(라운드 0 의 digester 병렬 호출) | 호출마다 그 루프에서 클라이언트를 만들고 닫는다. 루프에 묶인 가짜 클라이언트로 회귀 테스트 |
| CLI 가 넘긴 상대 경로가 git worktree 에서 하네스 저장소 기준으로 풀림 | **실제 진화 실행**(기준선 단계) | 실행 디렉터리를 절대 경로로 고정 |
| 프롬프트 구성요소가 `extra_blocks` 의 글(str)을 받지 못해 턴이 깨짐 | **실제 진화 실행**(gpt-6-sol 라운드 0 의 두 후보가 스모크에서 탈락) | 글과 `{"id","text"}` 를 모두 받는다. 그 라운드는 무효로 하고 같은 분석으로 다시 돌렸다(§6) |

## 10. 재현

정책 JSON(`{"provider", "model", "api_key"}`)과 RRSI 설정(`rrsi.json`, 역할 모델 포함)은 저장소 밖에 둔다.

```bash
rsi suite build runs/xgen-core
rsi suite build runs/xgen-hard --suite xgen-hard

# 실험 1·3 — geny vs geny-rsi H0
python experiments/compare_engines.py --policy sonnet5=policy-sonnet5.json --suite runs/xgen-hard --out runs/e3 --k 2
# 실험 2 — 결정적 재생 동등성
python experiments/replay_equivalence.py --policy sonnet5=policy-sonnet5.json --suite runs/xgen-core --tasks $(ls runs/xgen-core/tasks | sed 's/.json//') --out runs/e2b
# 실험 4 — RRSI 진화(기준선·δ 는 실험 3 의 측정을 jobs/base, jobs/base_r2 로 복사해 재사용할 수 있다)
rsi evolve init runs/evo-sonnet5 --suite runs/xgen-hard --policy policy-sonnet5.json --config rrsi-sonnet5.json
rsi evolve run runs/evo-sonnet5 --T 6
rsi evolve heldout runs/evo-sonnet5 final --k 4
# 실험 5 — Dream-RSI
experiments/dream_experiment.sh sonnet5 policy-sonnet5.json runs/xgen-hard runs/dream-sonnet5 0.02 runs/e3/sonnet5/geny-rsi/evolve
# 표
python experiments/summarize.py --runs runs --out docs/reports/data/2026-10-01.json
```
